# Viber 工作室：一条片子，三个 skill，一条流水线

三个 skill 各自都带一整套从头到尾的流程。这里只取每家最强的那一段，接成一条线：

| skill | 在这里负责 | 主要用到 |
|---|---|---|
| **xilo-opus-video** | 先给方案再动手：立项提问、三个方案 + 真预览、`brief.md`、自检打分 | `references/plan-format.md`、`brief-template.md`、`craft-rules.md`、`scripts/analyze_video.py`、`audio_tools.py` |
| **lemo-opuscar** | 风格库和生产线：43 张风格卡、导演手册、渲染 / 事件 / 阅读检查 / 音效 / 合成工具 | `$LIB/styles/<slug>/STYLE.md`、`DEMO.md`、`DIRECTOR.md`、`TECHNIQUE.md`、`$LIB/core/` |
| **huashu-art-motion** | 风格配方和把关：35 张风格配方（带渲染代码）、8 种解说语法、镜头语言、色板、镜头表检查、成片门禁 | `references/风格配方/`、`09-视频动画语法.md`、`动画语法/`、`镜头语言.md`、`镜头表模板.md`、`scripts/storyboard_lint.py`、`film_gate.py`、绘画库 |

两家的风格库加上本项目做过的画法，合在一个**风格目录**里（`refs/style-catalog/index.html`，由 `style_catalog.py` 生成）。每种风格一个 id：`lemo/<slug>`、`huashu/<id>`、`grammar/<id>`、`house/<名>`，选风格、写候选表、和用户对话都用它。

**哪一步用谁、读哪份文件、跑哪条命令，以本文为准**；和三个 skill 自己的 SKILL.md 冲突时听本文的。例如渲染一律用 lemo 的工具，不用 xilo 的 `render.py`（它用 file:// 打开页面，加载不了 `/core/lib.js` 和 three.js 模块），也不用 huashu 引擎的 `eras.js` 整片模式。

所有命令、路径和 Windows 上踩过的坑都在 [references/工具命令.md](references/工具命令.md)，动手前读一遍。下文用这几个名字：
`XILO=.claude/skills/xilo-opus-video`，`HUASHU=.claude/skills/huashu-art-motion`，`LIB=~/lemo-opuscar`（lemo 的风格库和工具），`<片>` = 作品文件夹。

## 走哪几步

- **新片**：第 1 步走到第 8 步，停四次。
- **改已有的片、出 vN+1**：画风不变就从第 6 或第 7 步开始（画风是第一版时用户在风格样片里挑定的）。**要换画风，从第 2 步风格样片走起**。

## 作品文件夹

每支片一个文件夹，放在仓库根目录（和 `berkson/`、`luanjiyuan/` 并列，会自动进 Git）：

```
<片>/
  brief.md          立项、风格样片的选择、三个方案、选定方案的完整 brief（xilo 七块）、声音表；末尾记每一轮的改动
  styles/           风格样片：candidates.json、每个候选一个页面文件夹（key.jpg）、styles_sheet.jpg；小样 mp4 不进仓库
  镜头表.md          huashu 格式的分镜，过 storyboard_lint
  previews/         三个方案的预览页（每个一个文件夹，同一套页面接口）
  index.html *.js   成片画面（页面接口见下）
  fonts/  lib/      字体；从 huashu 复制来的绘画库
  mix.py            声音（不要声音就删掉）
  build.sh          一条命令出片
  审片/              自检打分、门禁结果、独立审片、用户每一轮的意见
  CREDITS           用到的第三方素材、字体、乐器库和许可
  publish.md        发布文案（交付时写）
  versions/         每一版成片 vN.mp4、缩略图、README
  renders/ review/  中间产物（.gitignore 已忽略）
```

开新片：`sh .claude/skills/viber-studio/new_film.sh <片>`，复制好起手页面、`mix.py`、`build.sh` 和中文字体。

## 页面接口（全片、风格样片、预览页都用这一套）

```js
window.DUR = 秒数;
window.render = t => { … };            // 只由 t 决定：不用计时器、CSS 动画、不存上一帧状态，随机数带种子
window.EV = [{ t, type, … }];          // 画面上每个动作一条，mix.py 按它放音效
window.TEXTS = t => [{ id, text, x0, y0, x1, y1 }];   // 第 t 秒屏上所有的字，readcheck 查够不够时间读完
window.READY = true;                   // 字体、图片加载完再置位
```

起手模板 `starter/index.html` 已经写好这一套，按 1920 宽设计，草稿尺寸自动缩放。页面由 lemo 的服务器托管：本文件夹的文件用相对路径，lemo 库里的用绝对路径（`/core/lib.js`、`/node_modules/three/build/three.module.js`）。

要用 huashu 的笔刷、相机、图表等库，把 `util.js` 和用到的库从 `$HUASHU/scripts/engine/lib/` 复制进页面的 `lib/`，用 `<script src>` 按顺序加载，再调 `U.setStage(1920, 1080)`。这些库按舞台像素画（笔触、点的大小都是像素），所以**在 1920×1080 的离屏画布上画，最后 `drawImage` 缩放到页面**，草稿和正式版才是同一个样子。

## 第 1 步：立项（一次问完）

先读 `$XILO/SKILL.md` 第 1 步和 `$LIB/DIRECTOR.md` §1–3。然后**在一条消息里**问完会改变方案的事，用户已经说了的不再问：

- 题目和原材料：一个想法、文章、产品网址、参考视频都行。只给了方向、要我出题时，题目要落到观众这周的生活或当下热点上，不出纯知识清单。
- 时长、画幅：默认 16:9、1920×1080、30fps，时长按内容。
- **声音**：要不要配乐、拟音、旁白。不要默认有声，也不要默认无声，问。
- 自带素材：录音、音乐、照片、logo、字体。
- 片子类型：知识科普片另外读 `~/.claude/skills/vibe-knowledge-film/SKILL.md` 的讲解设计（找外行认得的形象、说到什么屏上就是什么），按它设计每一句的画面。

画风不在这里问，第 2 步用样片给用户挑。用户已经点名了某种画法（比如用 `/anatomy` 开头、说「用浮世绘」），记下来，它在第 2 步是第一个候选。

有参考视频：先说清来源，经同意再下载。然后跑 `analyze_video.py`，看切点和拼图；要细拆运动和节拍就跑 huashu 的 `breakdown.py`。参考只学结构和手法，不搬素材和文案。

建作品文件夹，把立项结果写进 `brief.md` 第一节。

## 第 2 步：风格样片 ⏸ 停一（必做）

**这一步不能跳过**（2026-10-22 用户定的）：用户自己点名了画法也照做，点名的那个是候选之一，样片照样做，让他和别的放在一起比。

1. **风格目录**：`refs/style-catalog/` 不在、或者三个上游 skill 更新过，先跑 `style_catalog.py`。目录用来自己挑候选，也给用户翻（`preview_start` 起 `style-catalog`）。
2. **挑候选**：一般 6 个；用户点名了画法时，点名的那个加至少 3 个别的。要同时满足：
   - **来源**：至少 2 个 lemo 风格卡、至少 2 个 huashu（风格配方或解说语法）。其余可以是本项目做过的画法、自由组合（`$XILO/references/code-stack.md`）或 Three.js 3D。
   - **一眼拉开**：任意两个不出自同一个类别（lemo 的类别、huashu 的「材料层 / 时代标本 / 解说语法」），深底浅底、平涂、笔触、3D 要混着来。
   - **贴题**：先读卡片上写的适用场景。huashu 配方优先选 ★★★；★★ 可以选，但要把卡上写的短板当风险说出来；★ 不选。时代标本只给致敬、穿越、速通这类题材。
   - **说实话**：纯代码画不出写实人物，也画不出新海诚那种繁复的手绘背景。题材需要这些时，把「AI 生成底图 + 代码合成」或「Three.js 3D」直接放进候选，不要硬上。
3. **定测试镜头**：从题目里挑**一个**最能代表全片的时刻（招牌镜头），所有候选都画这同一个时刻：同样的物、同样的动作、同一句字幕。这样用户比的只有风格。用一句话写进 `brief.md` 第二节，也写进 `candidates.json` 的 `moment`。
4. **做样片**：每个候选开一个页面：`sh new_film.sh <片>/styles/<序号>-<名> --page`。
   - 先读卡：lemo 读 `STYLE.md`（外观、配色、字体、动作、镜头语法、禁忌），技法看 `DEMO.md`；huashu 配方读配方卡，渲染器从 `scenes/<id>.js` 和 `lib/` 里拿（用库函数，不搬卡里那个房间、猫和少女的构图）；解说语法读 `动画语法/<id>.md`。
   - 3–4 秒，真代码、真字体、按卡片的规矩处理字幕；要有这个风格**自己的动法**（lemo 卡的动作和镜头语法，huashu 配方的「母题动作」）。画的是成片里会出现的样子，不是占位图。
   - 每个样片渲出 `key.jpg` 后自己先看一遍：字有没有溢出、主体是否清楚、像不像库里那个风格。像得不够就改，别把明显不像的拿给用户。
5. **拼图**：写 `<片>/styles/candidates.json`（格式见 `style_demos.py` 开头），跑 `style_demos.py <片>`，得到：
   - `styles_sheet.jpg`：每个候选一格，下面写编号、风格名、id、为什么适合、风险，右边配一张「库里的样子」作对照；
   - `styles_grid.mp4`：所有小样并排同时播放，比的是动起来的样子。

**停下来**：用 SendUserFile 发 `styles_sheet.jpg` 和 `styles_grid.mp4`，每个候选写两行：来自哪里（id）、为什么适合、最没把握的地方。告诉用户可以打开风格目录自己翻，点名别的 id 再做一轮。用户可以选一个，也可以混（「①的画法，③的讲法」），或者都不要、换一批。**没选定之前不进下一步**。选择和理由记进 `brief.md` 第二节。

## 第 3 步：三个方案 + 预览 ⏸ 停二

在选定的风格里出三个方案，格式按 `$XILO/references/plan-format.md`。风格已经定了，三个方案比的是怎么讲：

- xilo 的拉开方式：A 稳妥，B 换结构和画面组织，C 换讲法。
- huashu 的三方向硬门：三个方案的**构图**不同，不能只换调色。
- 选定的是 lemo 风格卡时，按 `STYLE.md` 的镜头语法想结构；选定的是 huashu 配方时，用卡里的「签名转场」和「母题动作」。

预览：把选定的那个样片页面复制成 `previews/plan-a|b|c`，在它上面搭每个方案最有代表性的那一个镜头，画法代码直接沿用。用 lemo 的 `still.mjs` 渲关键帧；卖点在运动的方案渲 2–4 秒小样。自己先看一遍，修掉字溢出、元素挤在一起、画面空这类问题。

**停下来**：把三个方案（每个一屏以内）和三张预览图一起给用户（用 SendUserFile 发图），请他选一个，或说怎么混、怎么改。没选定之前不进下一步。

## 第 4 步：定稿：brief + 镜头表 + 声音表

用户选定后，一口气写完三样：

1. **`brief.md`**：按 `$XILO/references/brief-template.md` 的七块写，已确认的全部写实。风格的规矩原样搬进 `<direction>`，不改：lemo 风格卡搬 `STYLE.md` 的外观、配色、字体、动作、镜头语法、声音、禁忌；huashu 配方搬「核心渲染器」「母题动作」「签名转场」，「当前短板」写成这支片要超过的地方；解说语法搬那张卡的镜头时长、缓动、转场。故事、结构、镜头由题目决定。**写完 brief 才打开 lemo 那张卡的 `DEMO.md`**，只学技法（笔刷、着色器、混音），不学它的故事和镜头。
2. **`镜头表.md`**：动笔前读 `$HUASHU/references/镜头语言.md` 一到四节，然后按 `$HUASHU/references/镜头表模板.md` 写。表前三行锁画风、色板、角色，然后一行一镜：物、动作、镜头、屏上字、做法。跑 `storyboard_lint.py`：**有红灯就改，红灯没清不写代码**；黄灯可以留，但要在 `brief.md` 里写明为什么。
3. **声音表**（用户要声音时）：写在 `brief.md` 里。参照 lemo `DIRECTOR.md` §6–7 和第 4 节的提示表、声音设计表：节拍网格、每段的环境底、主要拟音、音乐状态。每个拟音对应镜头表里的一个动作，最后都会变成页面里的一条 `EV`。

## 第 5 步：分镜（含风格帧）⏸ 停三

风格在第 2 步已经看过，这一步检查的是**成片画质**和镜头。挑 6–9 个关键镜头，用**正式的绘画代码**（就是成片要用的那套）各渲一帧，其中一张是全片的招牌镜头。有角色就加一张角色设定（正侧背、3–4 个表情、2–3 个姿势）。对照风格卡或配方卡逐条自查。

文件名写成 `s03_push_4s.jpg` 这样（镜号、镜头动作、时长，`sheet.py` 会把文件名印在图上），拼成一张分镜图，和一句话的故事梗概、镜头表一起给用户。说清楚这是最终画质，标出最没把握的一两镜。

**停下来**等用户通过。不满意就回第 5 步重画，或者回第 2 步换风格、回第 3 步换方案。**没通过之前，不把其他场景铺开做**。改动记进 `brief.md` 末尾的改动记录，并同步到镜头表和 brief。

## 第 6 步：制作

- **一镜一镜做**：每做完一镜，用 `still.mjs` 渲 3 张静帧自查：字有没有溢出、元素有没有重叠、主体够不够大、字停得够不够久。修好再做下一镜（xilo 第 5 步）。
- 所有镜头搭完，先 `sh <片>/build.sh --draft` 出 960×540 草稿，看节奏和转场。对了再精修细节。
- 运镜按 huashu 的镜头语言：镜头是标点；看得清就别动；快推和砸入只留给重音；推进去要有来有回。一张世界画布加一台相机，用 huashu 的 `camera.js`（CAM）或者自己写的 world→screen 函数，所有跟随主体的效果都经过它。
- 3D 走 Three.js：从 `/node_modules/three/` 引入。可以照 `luanjiyuan/` 的做法：`core.js` 放一个共享的 WebGL 渲染器，每个场景一个模块；隐藏剪切切在两边完全相同的帧上。经验另见 `$LIB/TECHNIQUE.md` §9。
- 声音：在页面的 `EV` 里登记每个画面动作；`mix.py` 用 lemo 的 `sfx.py` 合成拟音。配乐要采样乐器时，看 `$LIB/core/audio/INSTRUMENTS.md`，乐器库一个 70–400 MB，**下载前先问用户**。用户给了音乐的话，先跑 xilo 的 `audio_tools.py beats` 测出节拍表，镜头按拍子排。
- 正式出片：`sh <片>/build.sh` → `renders/final.mp4`。

## 第 7 步：验收 ⏸ 停四

按顺序做，每一项的结果都记进 `<片>/审片/`：

1. **readcheck**：`build.sh` 里已经包含，屏上的字停留不够就直接失败。
2. **自检打分**：用 xilo `analyze_video.py` 出抽帧拼图，再出一张手机尺寸的（`--cell-width 360`）。按 `$XILO/references/craft-rules.md` 的七项打分，列出最严重的 3 个问题和时间点。只重渲有问题的那几段，重复到每项 8 分以上。每轮记在 `审片/自检.md`。
3. **成片门禁**：跑 huashu `film_gate.py`。红灯（整片几乎没有快动作、中段空画面、蓝紫底）必须改；黄灯逐条写理由。结果存为 `审片/门禁-vN.txt`。
4. **不像样片**：用了 lemo 风格卡的，按 `DIRECTOR.md` §11 和那张卡的 `DEMO.md` 比六项（结构、开场、招牌镜头、运镜路径、配乐形状、结尾），至少四项不同。用了 huashu 配方的，确认没有搬卡里那个房间的构图、角色和家具。
5. **独立审片**：派一个没参与制作的 agent，只给它成片抽帧图、关键动作的连续帧条和 `brief.md`，让它挑毛病，结论写进 `审片/独立审片-vN.md`。这是用户同意过的流程，不用另外再问。
6. **本项目的硬规矩**（见下节），逐条对一遍。

**停下来**：把成片发给用户（`renders/final.mp4`），附上自检分数、门禁结论、独立审片挑出的问题，以及我认为还不够好的地方。请用户按「第几秒、哪个东西、改成什么」给意见。改完回到第 6 或第 7 步，每一轮的意见和改动都记进 `brief.md` 末尾。

## 第 8 步：存版本和交付

- 存版本按仓库 README 的规矩：`renders/final.mp4` **复制**成 `versions/vN.mp4`（不能用硬链接，ffmpeg 会原地截断文件）；生成缩略图；在 `versions/README.md` 加一行，第一次还要在根目录 README 的作品表里加一行；然后提交、打标签 `<片>-vN`、推送。
- 写 `CREDITS`（字体、乐器库、图片的来源和许可，用到的风格卡或配方也写上）和 `publish.md`（发布文案）。
- 告诉用户：成片路径、版本号、这次的关键创作决定、已知不足。

## 本项目的硬规矩（来自用户历次审片，每支片从第一版起就要做到）

- **风格要给得选**：每支新片先出风格样片，候选来自 lemo 和 huashu 两家的库，用户挑定了再往下做；用户点名了画法也照样出样片对比。
- **转场要连续**：同一个物在两镜都在（匹配剪辑），或者一条不停的运镜接过去；需要真切换场景时，切在两边完全相同的那一帧上。不要两个不相干的画面半透明叠化，不要黑场过渡，不要「推近 + 白闪」。转场放慢到能看清。运镜衔接处速度要连续，不能停一下再冲出去。
- **亮度不能突变**：转场里的明暗变化至少用 2 秒，走平滑的 S 曲线，不过冲，并逐帧量。
- **字要读得完**：标题、副标题完整清晰地停留约 2 秒才开始淡出；浅色或亮的 3D 背景上的字加柔和的暗底；标签不能被图标挡住。
- **画得具体**：建筑要有窗、招牌、门和道具；人画成有发型和衣服的扁平插画半身像，不用默认的剪影小人。比喻要一眼就懂，屏上的图示意思必须明显（比如用「10 次对 9 次」这样能数的点，不用意思不明的条形图）。
- **看得到画成了什么**（2026-10-23，duet）：镜头不能一直贴着笔尖。每画完一样东西就拉开、停一拍，让整幅画完整地在画面里；跟笔只做轻跟随。
- **所有镜头拼成同一幅大图**（2026-10-23，duet v2）：只围着局部做分镜不够。先定全片最后合成的那幅大图（duet v2：整条过山车轨道就是 Duet 图标那一笔），每一镜画的东西都是这幅图里的一块，片尾升起来让观众看到它们合在一起。方案阶段每个方案都要写清「大图是什么、每一镜在画哪一块」。转场也从这个概念里长出来（一趟不停的车：翻圈、倒挂停住、俯冲、升空），不用通用的推拉甩。
- **干净**（2026-10-23，duet）：要「干净」的片子，不靠乱麻、抖动、交叉的连线来表现紧张，改用速度、高度、节奏（越跑越快的圈、越堆越高的线圈、一下子停住）。连线走画外或沿着已有的线，不贴着边框再画第二道。
- **用真实的东西**（2026-10-23，duet）：讲产品连哪些 app，就画用户真正用的 app（官方字形和品牌色，Simple Icons 一类 CC0 来源），画面有足够的色彩。用到商标、官方 logo 先问用户；文章里没点名的功能或连接要告诉用户。
- **声音**：每个画面事件都配拟音；不用突然掐断的硬静音（听起来像出故障），改用低频轰鸣加自然衰减。没问过就不要假设有声音。
- **先给样子再铺开**：风格样片、方案预览、分镜三道关，就是为了在大量投入之前，先让用户看到真实的画面。
